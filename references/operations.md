# 命令与历史现场记录

以下历史样本结论不是本版本的发布验证；水印算法为启发式，仅针对打印页面，不能证明文件授权或所有布局无戳。

## 标准流程

```bash
# ① 只体检，不动图（先看有没有问题，最常用）
python scripts/dwgpipe.py audit "图纸.dwg"

# ② 体检 + 修复 + 清理，输出「已修复.dwg」和前后两份报告
python scripts/dwgpipe.py all "图纸.dwg" --out "输出"

# ③ 批量体检整个目录（.Attach 里的图不算主图，但会作为参照被一并处理）
python scripts/batch_check.py "D:\项目\图纸" --out "D:\项目\dwg-check"

# ④ 批量体检 + 修复
python scripts/batch_check.py "D:\项目\图纸" --repair
```

**修复永远发生在副本上，原图一个字节都不动。** 成品是 `<原名>-已修复.dwg`。
常规修复按原 DWG 格式显式另存，并核对成品文件头。比如 2013 版输入必须输出 2013 版。主图和参照都执行此检查，版本无法保留时报错。

## 命令速查

| 要什么 | 命令 |
|---|---|
| 只看问题清单 | `dwgpipe.py audit <dwg>` |
| 修完再验 | `dwgpipe.py all <dwg>` |
| 只修不清理（保守） | `dwgpipe.py all <dwg> --no-clean` |
| **判定有无教育版戳（唯一可信）** | `eduprint.py check <dwg或目录> --out 报告目录` 打印看四边水印 |
| **装 2022+ 后清戳（批量/整目录）** | `dwgpipe.py edustrip <dwg或目录>`　默认 `--verify print`：前后各打一次图 |
| 只清不验（快，但没有证据） | `edustrip <dwg> --verify none`　**别拿这个交活** |
| 引擎装在非标准位置 | `--acc <路径>`，或设环境变量 `ACCORECONSOLE` |
| 大图给足时间 | `--timeout 1800` |
| PURGE 多跑几轮（嵌套块深） | `--purge-rounds 5` |
| 连子目录一起扫 | `batch_check.py <dir> --recursive` |
| 不处理外部参照 | `--no-xref`（默认会跟随处理） |
| 参照的参照也处理 | `--xref-depth 2` |
| 保留中间件（排查用） | `--keep-temp`　默认跑完自动删 `%TEMP%\dwgfix\*`，一批图能堆几百 MB |

## 外部参照（默认跟随处理）

施工图的主图里装着几张参照图，只修主图等于白修——**参照默认一起处理**。

```bash
python scripts/dwgpipe.py all "D:\项目\图纸\建筑.dwg"
#   ├─ 主图：建筑-已修复.dwg + 前后报告
#   ├─ 参照：外部参照/<参照名>-已修复.dwg + 前后报告
#   ├─ 整包-已修复/建筑.dwg
#   │     └─ 总说明.dwg.Attach/详图.DWG
#   └─ 建筑-外部参照清单.md
```

**它怎么找参照**：从导出的 DXF 里读块定义的 `xref_path`（组码 1），
相对路径按主图所在目录解析。**找不到的会明确报「参照文件缺失」**——
这是真实问题（出图方少发文件），不是工具抽风。

| 规则 | 说明 |
|---|---|
| 处理范围 | 默认只跟一层（主图的直接参照）；`--xref-depth 2` 再往下追 |
| 去重 | 同一个参照被多张主图共用时只处理一次（批量模式共用 `seen` 集合） |
| 整包 | 修好的主图 + 参照按**原相对路径**摆进 `整包-已修复/`，直接能打开 |
| 原图 | 一律不动，参照也只在临时副本上改 |
| 暂存 | 处理主图时会把同目录的 `*.dwg.Attach` 复制进临时目录，让参照在**解析得到**的状态下跑 AUDIT/PURGE（默认跑完删除） |

**三条使用注意**

1. **别只替换参照文件。** 修好的参照是副本，文件名可能带前缀（重名时会加 Attach 目录名前缀）。
   要让主图用上，用 `整包-已修复/` 整个目录，或把副本按原名覆盖回 `.dwg.Attach`（先备份）。
2. **参照缺失 ≠ 修不了主图。** 缺的参照在报告里标出来，主图照常体检；
   但缺参照时主图里的底图内容本来就看不到，出图前必须补齐。
3. **参照也带教育版戳时**，修完照样弹框——戳在文件级，清洗管不了，见下文 EDU 章节。

## 判定口径

| 级别 | 含义 | 怎么处理 |
|---|---|---|
| 错误 | 会让后续操作出错（零长线、教育版、文件损坏） | 必须修 |
| 警告 | 影响质量/交付（0 层实体、重复线、超远图元、缺字体） | 建议修 |
| 提示 | 只是不干净（空图层、未用块、空布局） | 按需，PURGE 顺手就清了 |

完整规则表见 `references/checklist.md`。

**文件大小不能当清理效果的唯一指标。** 实测（一张 451,794 字节的施工图）：什么都不删、只
`QSAVE` 重存一遍，文件反而涨到 496,089 B（+9.8%）—— 不同 AutoCAD 版本/构建写盘密度不同，
重存本身就会膨胀。清洗后 485,649 B，比裸重存小约 10 KB，这才是清理真正省下的量。
而且同样操作连跑两次得到 485,494 / 485,649 B（DWG 内含 GUID/时间戳），字节数本身不稳定。
判断清理是否有效看**实体数、图层/块/样式数、问题数**，别看字节数。


## 教育版（EDU）处理

> 2026-11-24 用 JTB World 官方的「带戳 / 不带戳」成对样本（`EduFinderSampleDWGs.zip`）
> 全套实测重写过。下面每条都有对照组撑着，不是抄来的说法。

### 一、判定：打印出来看四边水印（唯一可信）

```bash
python scripts/eduprint.py check "图.dwg" --out 报告目录
python scripts/eduprint.py check "D:\项目\图纸" --out "D:\项目\图纸\eduprint"
```

做法：复制 dwg（连同 `*.dwg.Attach` 参照、常用 SHX）到纯英文临时目录 →
`accoreconsole -plot` 打 DWG To PDF → 渲染成图 → 看**页面最外 10% 边条**。

判据不是「边条有多黑」，而是「这条边是不是那行 AUTODESK 的字」：

| 特征 | 带戳的边条 | 图面内容伸进边条 |
|---|---|---|
| 连通块个数 | **6~10（正好 8 个字母）** | 3 块、26 块、47 块、271 块…… |
| 暗像素占比 | **0.6~0.8%（很稳）** | 0.22% / 0.65% / 0.87% / 9.4%，五花八门 |
| 沿边长度占比 | 8~15% | 5~100% |
| 分布 | 四边都有同一行字 | 通常只在一两条边 |

判定：**某条边精确命中（6~10 块 + 暗 0.55~0.9% + 沿边 5~20%）**，或
**两条以上宽口径命中且深浅接近**（差 ≤1.6 倍）→ 带戳。
内容把其余几条边压住、只露出一两条的情况也认——实测就有图右边被平面图盖满，
只剩 3 条边露水印。

**为什么必须看形态、不能看比例**：那批干净图里有图的边条暗像素能到
8.7%（右边全是图框和平面图）、0.87%（下边一排小图块）——比很多真带戳的还黑；
而真带戳的稳定在 0.6~0.8%。第一版按「边条暗 0.10% 就算带戳」跑，16 张里误判 10 张。

标定（29 张打印件，实测全套 + 对照）：

| 判据版本 | 真带戳 → 判带戳 | 真干净 → 判干净 | 矛盾 |
|---|---|---|---|
| 0.10% 阈值 | 7/8 | 8/21 | **10 处** |
| 水印指纹（现行） | **8/8** | **21/21** | **0** |

每张都留 `打印验收/<名>-打印-前|后.pdf/.png`，可直接翻图核对。

> ### ⚠️ `educheck` 的开图判据已作废，别再用
>
> 旧说「抓 `按 ENTER 键继续:` 就是带戳」。这行的真身是：它出现在

>
> 决定性对照：把全部字体、所有 `*.dwg.Attach` 参照都补齐后，
> **一张干净的图和一张带戳的图弹得一字不差**（都是那 2 个系统变量）。
> 原以为是「字体替换框 / 参照未找到框」在冒充，其实补全了也照样弹。
>
> 代码还留着（`educheck` 模式会打警告），但**结果不可信**，判戳一律用 `eduprint`。

> 早期用 JTB World 官方成对样本（`EduFinderSampleDWGs.zip`）校准过开图判据，
> 那批样本参照字体都齐、恰好命中，所以当时看着是对的。实际工程图一上就崩，
> 原因见上面的 SYSVARMONITOR 说明。官方样本现在只当「带戳文件长什么样」的参照物。

**两条走不通的路，别再试：**
1. **字节特征扫描无效。** DWG 数据段压缩，连 `AcDb:` 都看不见（451KB 的图里只出现 1 次）。
   官方带戳样本里 `ACAD_EDU` / `Educational` / `教育版`GBK **一个都搜不到**。
2. **DXF 明文扫描无效。** 每张图的 DXF 都有 `ACDSDATA` 段，但带戳 / 干净两张的
   DXF 内容一模一样，戳不在文本层。

### 二、洗不掉（实测，和网上的老偏方相反）

| 手段 | 结果 |
|---|---|
| DXF 往返（DXFOUT → SAVEAS 2018） | **仍带戳** |
| 商业版 AutoCAD 2020 另存 | **仍带戳** |
| 把图元全删光再另存 | **仍带戳**（戳是文件级，不随内容） |
| 官方口径 | 只有 **AutoCAD 2022+** 打开另存能清 |

所以手上只有 2020 内核时，**没有**本地清戳手段。要清只能：换 2022+ 过一遍，或让出图方重出。

> **实测否决：DWG TrueView 不能用来清戳。**
> TrueView 2027（内核 26.0.156.0，`accoreconsole` 版本 X.156.0.0）实测：
> 能装、能开图、能出图，但 `QSAVE` / `SAVEAS` / `AUDIT` / `DXFOUT` **全是
> "Unknown command"**，连 `FILEDIA` 都不可用，LISP 也被禁用
> （`(setvar LISP command is not available`）。它是只读查看器内核，**没有任何写盘路径**，
> 所以清不了戳。别再往这条路上花时间。
>
> 同期发现的两个坑，重跑前必看：
> - **Git Bash 会把 `/i` 之类的参数改写成 `C:/Program Files/Git/i`**，导致
>   `accoreconsole` 打印 usage 并退出 `ErrorStatus=53`。调无头引擎时先
>   `export MSYS2_ARG_CONV_EXCL='*'`，或直接用 Python `subprocess` 传参。
> - **残缺 / 破解版 AutoCAD 的 `accoreconsole` 会一启动就段错误**（exit 139，
>   banner 能打印出来但脚本一行不执行）。判据：目录里缺 `adlmint.dll`、
>   `AdskLicensingSDK_4.dll`，文件数与体积明显偏小（正常 AutoCAD 2022 约 2.5GB / 4000+ 文件；
>   残缺版只有 1322MB / 1815 文件）。实测两个绿色精简版都是这个症状。

### 三、装了 2022+ 之后：`edustrip` 一键清（无头，批量）

```bash
# 单张 / 多张 / 整个目录都行，带戳的才处理，干净的自动跳过
python scripts/dwgpipe.py edustrip "图.dwg"
python scripts/dwgpipe.py edustrip "D:\项目\图纸" --out "D:\项目\图纸\dwg-check"
```

流程是三步闭环，不是盲改：

1. **判定**（非教育版内核打印）—— 不带戳直接跳过，不动文件
2. **清戳**（2022+ 内核）—— 打开 →（可选 `AUDIT`）→ `QSAVE` 原地重写。只有官方这条路径
3. **复验**（再打印一次）—— 还带戳就报「仍带戳，需人工」，绝不假装成功

产物：`<名>-已去戳.dwg` + `去戳报告.md` + `edustrip.json` + `打印验收/<名>-打印-前|后.png`。
原图不动。

**前后都打印，用打印法判定与验收。** 开图判据已作废（SYSVARMONITOR），没有便宜办法了：

| `--verify` | 处理前 | 处理后验收 | 适用 |
|---|---|---|---|
| `print`（默认） | 打印法 | 打印法 | 全部场景，每张多花十几秒 |
| `none` | 跳过 | 跳过 | 只清不验，**没有证据，别拿这个交活** |

控制台会同时给结论和依据：

```
清戳前：带戳　清戳后：干净 ✓
处理前依据：4 条边精确命中、共 4 条边有同形态文字（bottom/left/right/top），判为带戳
处理后依据：无边的暗像素形态像水印　边条暗像素 0.8% → 0.0%
```

「依据」比结论更该看——它说明判的是四边都有那行 8 个字母的字，不是「边条有点黑」。

**参照默认一起清。** 把目录丢进来时，`*.dwg.Attach` 里的参照也在目标里
（戳会从参照传回主图，只清主图等于白清）；不想要加 `--no-xref`。
单张图给进来时只处理这一张。

实测一套 16 张的住宅施工图（5 主图 + 11 参照）：**已清 8，本来就干净 8，失败 0**。
其中三张（建筑 / 暖通 / 给排水说明）曾被第一版判据（按边条黑多少）误判成带戳——
它们边条暗像素 0.22% / 0.87% / 9.4%，比真戳还黑，但形态是图框和平面图，不是那行字。

设计上的三个要点，改代码前先看：

- **判定内核和清戳内核是两个，别合并。** 判定/打印必须用非教育版内核（默认取最老的那个）；
  清戳必须 2022+。拿教育版授权的 2022 去打印，它会给每张图都盖戳，全目录判成带戳。
- **清戳内核找不到就降级成「只判定」。** 批量几百张里可能只有几张带戳，
  先判出来再决定要不要装 2022，别为了判定先去装软件。
- **`QSAVE` 前重设一次 `FILEDIA`。** 2022 开带戳图时那个框会被压平成
  「按 ENTER 键继续:」，吃掉一行输入；脚本开头留两个空行吸收，关键命令前再设一次，
  不指望开头几行还在。跑完看输出里有没有 `[MARK-QSAVE]` 就知道另存是否真的执行了。
- **验收必须前后各打一次。** 只打一次没有对照，分不清「水印被去掉」和「本来就没有」。
  两份都留在 `打印验收/`，是能直接翻图复核的硬证据。

> 授权提醒：2022+ 用 `AdskLicensing`，未登录/未激活时 `accoreconsole` 会直接退出，
> 输出里带「许可证 / License」字样，脚本会把这行标出来。别把授权问题当成「清不掉」。

### 四、传染规则（决定怎么补救）

| 操作 | 宿主会不会弹框 |
|---|---|
| 主图 `XREF` 一张带戳的图 | **会弹**（但主图自己没被写入标记，拆掉参照就恢复） |
| 干净图 `INSERT` 一张带戳的图 | **不会**（2019+ 已不传染） |

推论：**"把整张图作为块插进一张干净新图"这个偏方是有效的**，代价是
图纸空间、布局、打印设置都搬不过去——只适合模型空间单布局的图。

## 实测坑（必读，都是真踩过的）

1. **`-OVERKILL` 会挂死无头会话。** 实测：命令本身跑完了，但进程退出时卡住，
   后续 `QSAVE`/`DXFOUT` 全不执行，150 秒超时仍未返回。
   → 已从流水线移除。重复实体只报告，让人在 GUI 里跑 OVERKILL。
2. **`accoreconsole` 的 stdout 能拿到，但必须按 UTF-16LE 解码。**
   屏幕上那行 `Redirect stdout (file: ...)` 是个幌子，`subprocess` 是能收到内容的：
   `p.stdout.decode("utf-16-le")`。历史开图判定曾使用这条通道（现已废弃）——
   模态对话框被压平成 `按 ENTER 键继续:` 后正是从这里出来的。
   （需要 LISP 自己写文件的场合：要结构化数据、或要 GBK 原文时。）
3. **`AUDIT` 的结论只在 `.adt` 里。** 必须 `(setvar "AUDITCTL" 1)`，
   `.adt` 和 DWG 同目录同名，**GBK 编码**，关键句是「共发现 N 个错误，已修复 N 个」。
4. **`SAVEAS` 参数顺序固定是「格式 → 文件名」**：`(vl-cmdf "_.SAVEAS" "2018" "x.dwg")`。
   反序会挂死；`"R12"` / `"R12 DXF"` 这类格式 token 不被接受，也会挂死。
5. **`scr` 必须是纯 ASCII，注释也不能有中文。** 中文注释会让整个脚本解析失败，
   报错信息完全不指向真正原因。
6. **不带 `/i` 直接跑会报 `ErrorStatus=53`。** 必须 `/i <某个存盘 dwg> /s <scr>`。
7. **`DXFOUT` 只吃「文件名 + 精度」两个参数。** 多给参数会吃掉后续脚本输入，
   命令只做一半就断，但**文件已经生成了**，很容易误判成成功。
8. **新建实体可能跑进当前布局，不在模型空间。** 布局是激活状态时 `entmake` 落到图纸空间，
   查模型空间就"看不见"。→ 造图先 `(setvar "TILEMODE" 1)`；
   体检必须遍历**所有 layout**，不能只 `doc.modelspace()`。
9. **常规修复在 DWG 副本上执行，并按原格式 `SAVEAS` 到独立文件。** 文件头版本码一致且修后 DXF 可读，才发布修复成品。
10. **同一时刻只跑一个 `accoreconsole`。** 并发会抢同一份 profile，行为不可预测。
   批量是串行的。
11. **`.dwl` / `.dwl2` 是锁文件。** 目录里见到先确认没有 `acad.exe` 进程，
    有就是残留，可以直接删；`.dwg.Attach` 目录是 xref 缓存，**不能删**。
12. **中文参照目录名不影响解析，别被「路径含非 ASCII」那条吓到。** 实测把 5 个中文命名的
    `.dwg.Attach` 目录整批复制进纯 ASCII 临时目录，`in.dwg` 里的相对参照全部解析成功，
    只有真缺的两个文件报「未找到」。中文只对 `accoreconsole` 的 `/i` `/s` **参数**有害，
    对 CAD 内部按相对路径找参照没影响 —— 所以暂存房间用 `in.dwg` 这种 ASCII 名就够了。
13. **`report.json` / `batch.json` 结构变了**（2026-11 起）：单文件是
    `{main: {...}, refs: [...]}`，批量是 `{main: [...], xref: [...]}`。
    老脚本如果直接 `json.loads(...)` 当列表迭代会炸。
